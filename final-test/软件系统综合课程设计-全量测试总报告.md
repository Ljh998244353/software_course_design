## 三、项目简介

在线拍卖平台是面向校园或小型社区场景的 Web 拍卖系统，主流程为：

```text
注册/登录 -> 卖家发布拍品 -> 管理员审核 -> 管理员创建拍卖 -> 买家竞价
-> 拍卖结束生成订单 -> 本地测试支付 -> 发货/收货 -> 双方评价
-> 通知、统计、运维闭环
```

系统采用“前后端分离 + 模块化分层单体”的架构。后端由 C++ Drogon 应用提供 REST API、WebSocket、调度任务和核心业务服务；MySQL 是拍卖、出价、订单、支付等交易事实的唯一来源；前端位于 `frontend/`，使用 Next.js App Router 访问真实 HTTP 与 WebSocket 接口。

当前支付口径为本地测试支付模型：前端支付页传 `confirm_success=true` 时，由后端 mock 成功回调推进订单状态，未接入真实第三方支付平台。

## 十五、环境问题处理记录

1. 首次 `cmake --build build` 使用了旧 CMake 缓存中的 Windows clang：`/mnt/c/Program Files/LLVM/bin/clang++.exe`，在 WSL 中触发 `UtilBindVsockAnyPort: socket failed 1`。按用户确认后重新配置为 `/usr/bin/c++` 并构建通过。
2. 沙箱内单独执行 `scripts/test.sh security` 时，mysqld 无法创建 Unix/TCP socket；非沙箱执行通过。该情况只影响测试环境启动，不影响安全用例断言。
3. `scripts/db/setup_local_mysql.sh` 原默认目录 `run-$$` 在当前执行环境中可能复用旧数据目录，已修复为短随机目录，避免 `ibdata1` lock 冲突，同时保持 socket 路径不过长。
4. JMeter 脚本要求后端先启动。首次运行因 `127.0.0.1:18080` 未启动而退出；随后按主入口启动后端-only 后重跑通过。
