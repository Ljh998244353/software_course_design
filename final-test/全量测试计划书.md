# 在线拍卖平台全量测试计划书

## 1. 测试目标

本计划用于后续对 `/home/ljh/project/soft_course_design` 在线拍卖平台执行一次全量验收测试，并将执行过程、日志、截图、性能数据和缺陷记录统一沉淀到 `final-test/`。

本轮全量测试目标：

1. 覆盖用户注册登录、物品发布、管理员审核、拍卖创建、浏览详情、竞价、拍卖结束、订单支付、发货收货、评价、通知、统计和运维入口。
2. 同时执行黑盒测试、白盒测试、单元/模块测试、集成测试、浏览器 E2E、性能/负载测试、安全负向测试和可靠性专项测试。
3. 重点验证竞价最高价一致性、拍卖结束与出价竞争、单拍卖单订单、支付回调幂等、RBAC、账号冻结、通知失败不回滚主交易等核心不变量。
4. 明确哪些测试直接通过现有工具执行，哪些需要在执行阶段补充结果观察、截图或缺陷记录。
5. 建立需求、模块、风险、命令和证据之间的追踪矩阵，避免只跑 happy path 或只凭浏览器表象判断通过。
6. 对所有未执行、环境受限、工具缺失或结果不稳定的项目明确登记为缺口或缺陷，不能合并进“已通过”结论。
7. 按课程 final Word 报告形式补齐 4 人份测试分工、用例、脚本和结果，但最终在 `final-test/` 下统一成一份总报告：[软件系统综合课程设计-全量测试总报告.md](/home/ljh/project/soft_course_design/final-test/软件系统综合课程设计-全量测试总报告.md)。

## 5. 测试分层与方法

### 5.0 分层门禁原则

关键业务规则不能只靠浏览器 E2E 证明通过。每个高风险链路必须至少同时具备下列证据：

- 一个底层或模块级断言，证明领域规则、状态机或幂等判断正确。
- 一个真实数据库或 HTTP 集成断言，证明事务、约束、状态落库和错误码正确。
- 一个用户视角黑盒断言，证明前端页面、会话、表单和业务反馈可用。
- 对竞价、拍卖结束、支付回调和 RBAC，必须补充负向、重复请求或并发场景。
- 对通知、缓存、WebSocket、统计任务等旁路能力，必须证明失败不会破坏主交易事实。

### 5.1 单元与模块测试

| 测试层 | 命令 | 覆盖重点 |
|---|---|---|
| 冒烟/配置 | `scripts/test.sh smoke` | 配置加载、统一响应、错误码、健康检查 |
| 数据库冒烟 | `scripts/test.sh db` | schema、seed、应用连库、`--check-db` |
| 模块测试 | `scripts/test.sh module` | auth、item、auction、bid、order、payment、review、statistics、ops |
| 单模块回归 | `scripts/test.sh auth/item/auction/bid/order/payment/review/statistics/ops` | 定位失败模块 |
| 全量 CTest | `ctest --test-dir build --output-on-failure` | 当前 16 项后端测试全量回归 |

单元测试判定方法：

- 业务规则用 assert 直接验证返回值、状态、错误码。
- 交易链路用数据库事实状态验证最终结果。
- 对拍卖、竞价、支付等关键模块必须包含失败路径和重复请求路径。
- 用例不得依赖执行顺序；若需要共享准备数据，必须在脚本或 fixture 中显式创建。
- 高风险模块建议在执行阶段补充覆盖率或等价检查记录：竞价、拍卖关闭、订单生成、支付回调、认证权限优先。

### 5.2 白盒测试

白盒测试采用源码审查、控制流/条件覆盖检查和已有 C++ 测试验证结合的方式。

| 白盒对象 | 代码位置 | 检查方法 |
|---|---|---|
| 拍卖配置与结束处理 | `src/modules/auction/auction_service.cpp` | 基本路径、状态机、结束时间二次确认、单订单前置条件 |
| 出价受理与延时保护 | `src/modules/bid/bid_service.cpp`、`src/repository/bid_repository.cpp` | 条件判定、事务内最高价更新、幂等键、通知失败旁路 |
| 订单生成与履约 | `src/modules/order/`、`src/repository/order_repository.cpp` | 订单状态机、单拍卖单订单、发货/收货权限 |
| 支付回调 | `src/modules/payment/`、`src/access/http/payment_http.cpp` | 签名、金额、流水号、重复回调、审计日志 |
| 认证与 RBAC | `src/modules/auth/`、`src/middleware/auth_middleware.cpp` | token、角色、冻结账号、越权拒绝 |
| 通知/统计/运维 | `src/modules/notification`、`statistics`、`ops` | 主交易隔离、重试补偿、任务日志、查询权限 |

白盒输出记录在 `final-test/白盒测试记录.md`，至少记录：被测函数、关键分支、现有用例覆盖情况、发现的代码/文档差异、是否需要补充回归用例。

白盒检查必须覆盖以下分支类别：

- 成功路径、参数缺失、非法状态、边界金额、重复请求、权限失败。
- 事务提交前失败、事务提交后旁路失败、重复任务重试、通知或缓存降级。
- 状态机合法迁移和非法越级迁移。
- 错误码、响应字段和前端依赖字段是否与接口文档和 `frontend/API_READINESS.md` 一致。

### 5.3 黑盒 API 测试

| 测试点 | 方法 | 预期 |
|---|---|---|
| 认证会话 | 登录、注册、当前用户、登出、冻结登录 | 正确返回 token/401/403，冻结账号不可继续操作 |
| 拍品发布 | 创建、图片、编辑、提交审核、提交后禁止编辑 | 状态按 `DRAFT -> PENDING_AUDIT` 流转 |
| 审核与建拍 | 管理员通过/驳回、创建/修改/取消拍卖 | 非管理员拒绝，审核日志可查 |
| 公开拍卖 | 列表、详情、当前价、出价历史、非法筛选 | 响应结构稳定，非法参数返回业务错误 |
| 出价 | 有效出价、低价、重复幂等键、过期、冻结用户 | 最高价唯一，失败不污染事实数据 |
| 订单支付 | 订单列表、详情、支付发起、坏签名、成功回调、重复回调 | 支付幂等，坏签名不推进订单 |
| 履约评价 | 发货、收货、评价、重复评价、信用摘要 | 状态机不可越级，重复评价拒绝 |
| 通知统计运维 | 通知列表/已读、日报重跑/导出、异常标记、补偿、通知重试 | RBAC 正确，日志可追踪 |

API 黑盒还必须记录：

- 每个关键接口的成功响应字段、稳定错误码、HTTP 状态码和鉴权行为。
- 列表接口的分页、空结果、非法筛选、边界日期和排序表现。
- POST/PATCH 类接口的重复提交、缺失字段、非法枚举、越权角色和冻结用户行为。
- 支付回调类接口的签名、金额、订单号、商户流水号、回调状态和重复回调矩阵。
- WebSocket 建连失败时，HTTP 轮询是否能继续读到 MySQL 最终事实。

执行入口：

```bash
scripts/test.sh http
scripts/deploy/verify_release.sh
scripts/deploy/verify_release.sh --full
```

## 7. 性能与负载测试计划

### 7.1 指标阈值

| 指标 | 阈值 |

## 8. 安全、可靠性与高风险专项

| 类型 | 命令 | 重点 |
|---|---|---|
| 高风险专项 | `scripts/test.sh risk` | 并发出价、结束竞争、结算竞争、支付并发幂等、缓存降级、通知失败重试 |
| 压力/并发专项 | `scripts/test.sh stress` | 竞价竞争、订单生成竞争、回调重复 |
| 安全负向 | `scripts/test.sh security` | 未认证、越权、冻结账号、非法金额、幂等冲突、支付回调篡改 |
| 发布门禁 | `scripts/deploy/verify_release.sh --full` | 前端构建、后端真实服务、HTTP、risk、ctest、e2e、性能 |

专项通过准则：

- 同一拍卖最终只有一个最高价和最高出价者。
- 出价历史与最终拍卖状态一致。
- 拍卖结束后不得接受新有效出价。
- 同一拍卖最多生成一笔订单。
- 重复支付成功回调不重复推进订单或记账。
- 通知失败、缓存失败不回滚主交易。
- 管理/运维操作保留可追踪日志。

故障注入与恢复矩阵：

| 场景 | 注入方法 | 期望行为 | 证据 |
|---|---|---|---|
| WebSocket 不可用 | 阻断或关闭 WS 连接后刷新详情 | 页面降级轮询，最高价仍以后端为准 | 浏览器日志、网络请求、页面截图 |
| 通知发送失败 | 使用现有 risk/ops 用例或人工制造通知重试失败 | 出价/支付主交易已提交，通知进入失败或重试记录 | 数据库事实、任务日志 |
| 重复支付回调 | 重放同一成功回调或同一业务流水 | 订单只推进一次，支付记录和审计可追踪 | `scripts/test.sh payment`、日志 |
| 拍卖关闭与晚到出价竞争 | risk/stress 构造 close job 与 late bid | 不接受结束后的有效出价，最多一笔订单 | `scripts/test.sh risk`、数据库核验 |
| 冻结账号操作 | 冻结用户登录、出价、查看受保护资源 | 拒绝状态变更，返回稳定错误 | `scripts/test.sh security`、Selenium |
| MySQL/配置异常 | 使用独立测试配置触发连库失败或缺表检查 | 服务给出可诊断错误，不产生半写状态 | `--check-db`、server log |
| 统计/补偿任务重跑 | 重复触发日报或补偿入口 | 结果幂等，任务日志保留执行记录 | `scripts/test.sh statistics`、`scripts/test.sh ops` |
