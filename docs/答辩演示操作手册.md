# 在线拍卖平台答辩演示操作手册

## 1. 演示目标

本手册用于答辩现场按固定数据复现完整业务闭环，并说明对应的自动化浏览器验证方式。

本次演示覆盖：

- 认证与权限：注册、登录、管理员与普通用户入口隔离。
- 拍品与审核：卖家发布拍品、图片 URL 校验、提交审核、管理员批准。
- 拍卖管理：管理员创建拍卖、查看运行中拍卖。
- 竞价与实时：买家浏览大厅、详情页出价、第二买家加价、价格刷新。
- 订单与支付：中标用户查看订单、使用本地测试支付模型完成支付。
- 履约与评价：卖家发货、买家确认收货、买家评价。
- 通知与统计运维：卖家收到评价通知、管理员查看 GMV、操作日志和通知重试。

当前主入口：

```text
前端：http://127.0.0.1:3000
后端：http://127.0.0.1:18080
```

历史 `/demo` 只读演示台不作为当前主验收入口；当前以 `frontend/` 真实业务前端和后端 `/api/...`、`/ws/...` 为准。


## 4. 人工答辩演示流程

### Step 1：注册第二买家

1. 打开 `http://127.0.0.1:3000/auth/login`。
2. 点击 `注册`。
3. 填写：
   - 用户名：`viewer_demo`
   - 昵称：`第二买家`
   - 邮箱：`viewer_demo@example.test`
   - 手机号：`13800000004`
   - 密码：`Viewer@123`
4. 点击 `注册并进入大厅`。

验证点：

- 页面跳转到 `/auction/hall`。
- 页面标题显示 `拍卖大厅`。
- 如果提示用户名已存在，说明该账号已在本地库中，改为直接登录 `viewer_demo / Viewer@123`，不影响后续演示。

### Step 2：卖家发布拍品

1. 进入 `http://127.0.0.1:3000/auth/login`。
2. 使用 `seller_demo / Seller@123` 登录。
3. 进入导航栏 `发布拍品`，或直接打开 `/auction/publish`。
4. 第一步 `描述拍品` 填写：
   - 拍品标题：`答辩演示 iPad Air 5 64G 蓝色`
   - 分类 ID：`1`
   - 拍品描述：`99 新，无拆修，支持犀浦校区当面验货，适合课程答辩完整链路演示。`
5. 点击 `下一步`。
6. 第二步 `上传实拍` 填写图片 URL：
   - `http://127.0.0.1:3000/demo-auction.svg`
7. 点击 `添加图片`，等待出现 `图片已添加`。
8. 点击 `下一步`。
9. 第三步 `建议竞价配置` 填写：
   - 起拍价：`300`
   - 建议最小加价幅度：`20`
   - 建议延时保护窗口（秒）：`300`
   - 建议顺延秒数：`180`
   - 交付地点：`犀浦校区东门`
   - 标签（逗号分隔）：`99新,可当面验货,答辩演示`
10. 点击 `下一步`。
11. 第四步确认 `图片数量`、价格和标签无误后，点击精确按钮 `提交审核`。

验证点：

- 页面提示 `提交成功，拍品 #... 已进入审核队列`。
- 发布页使用真实 `/api/items`、`/api/items/{id}/images`、`/api/items/{id}/submit-review`。
- 本地图片 URL 会经过前端图片加载校验，能证明不是静态跳过表单校验。

### Step 3：管理员审核拍品

1. 使用 `admin / Admin@123` 登录。
2. 打开 `/admin/dashboard`。
3. 确认页面标题为 `审核与运维大盘`。
4. 在 `待审核拍品` 表格中找到 `答辩演示 iPad Air 5 64G 蓝色`。
5. 点击该拍品行，右侧打开 `REVIEW DRAWER`。
6. 检查卖家、交付地点、图片和标题。
7. 点击 `批准`。

验证点：

- 待审核列表中的该拍品消失。
- `最近处理记录` 中出现该拍品，状态为 `已批准`。
- 说明管理员权限、审核状态机和审核日志链路生效。

### Step 4：管理员创建拍卖

1. 在 `最近处理记录` 中找到刚批准的拍品。
2. 点击 `创建拍卖`。
3. 为了现场快速生成订单，不使用默认 24 小时结束时间，明确填写：
   - 开始时间：当前时间后约 1 分钟
   - 结束时间：当前时间后约 4 分钟
   - 起拍价：`300`
   - 最小加价：`20`
   - 延时窗口秒数：`0`
   - 每次延长秒数：`0`
4. 点击 `确认创建拍卖`。
5. 点击左侧 `拍卖监控`。

验证点：

- 最近处理记录显示 `已创建拍卖 #...`。
- `拍卖监控` 表中出现 `答辩演示 iPad Air 5 64G 蓝色`。
- 当前价为 `¥300`，最小加价为 `¥20`。
- 如果状态暂时是 `PENDING_START`，等待 1 分钟内后台调度自动切换为 `RUNNING` 后再继续出价。

### Step 5：第一买家出价

1. 使用 `buyer_demo / Buyer@123` 登录。
2. 打开 `/auction/hall`。
3. 找到 `答辩演示 iPad Air 5 64G 蓝色`。
4. 点击拍品卡片进入详情页。
5. 确认详情页标题为该拍品标题，当前价为 `¥300`。
6. 在出价输入框填入 `340`。
7. 点击 `PLACE BID`。

验证点：

- 页面提示 `出价成功，权威价格已刷新`。
- 当前价刷新到 `¥340`。
- 出价历史出现 `¥340`。
- 该步骤验证 `/api/auctions/{id}`、`/api/auctions/{id}/bids` 和详情实时刷新逻辑。
- 如果大厅还没有出现该拍卖，说明开始调度尚未到达，刷新页面或等待约 1 分钟。

### Step 6：第二买家加价并成为中标者

1. 使用 `viewer_demo / Viewer@123` 登录。
2. 打开同一个拍卖详情页。
3. 在出价输入框填入 `380`。
4. 点击 `PLACE BID`。

验证点：

- 页面提示 `出价成功，权威价格已刷新`。
- 当前价刷新到 `¥380`。
- 出价历史中 `viewer_demo` 对应的出价为当前领先出价。
- 第一买家的 `340` 被挤出最高价，证明最高价状态会随新有效出价更新。

### Step 7：等待拍卖结束并生成订单

1. 第二买家出价后，等待到管理员建拍时填写的结束时间。
2. 后端启动时已注册 1 秒周期调度：
   - 拍卖开始调度
   - 拍卖结束调度
   - 订单结算调度
3. 结束时间到达后，等待 3 到 5 秒。
4. 继续使用 `viewer_demo / Viewer@123` 打开 `/orders`。
5. 找到 `答辩演示 iPad Air 5 64G 蓝色` 对应订单。

验证点：

- 订单状态为 `待支付`。
- 订单金额为 `¥380`。
- 说明真实业务规则是“拍卖结束后由调度进入 `SETTLING`，再由订单结算生成一笔订单”，不是出价后立即生成订单。

### Step 8：中标买家支付订单

1. 在 `viewer_demo` 的订单列表中点击 `支付`。
2. 进入 `/checkout/{orderId}` 后确认：
   - 页面标题为 `订单支付`
   - 金额为 `¥380`
3. 点击 `确认支付`。

验证点：

- 页面跳转或显示 `支付成功`。
- 当前支付是本地测试支付模型：前端提交 `confirm_success=true`，后端 mock 成功回调推进订单状态。
- 不宣称已接入真实第三方支付平台。

### Step 9：卖家发货

1. 使用 `seller_demo / Seller@123` 登录。
2. 打开 `/orders`。
3. 找到同一订单。
4. 点击 `发货`。

验证点：

- 页面提示 `已确认发货`。
- 订单状态变为 `已发货`。
- 说明卖家履约动作和订单状态机推进成功。

### Step 10：买家确认收货并评价

1. 使用 `viewer_demo / Viewer@123` 登录。
2. 打开 `/orders`。
3. 找到同一订单。
4. 点击 `收货`。
5. 等待订单状态变为 `已完成`。
6. 评分选择 `5`。
7. 评价内容保留默认 `交易顺利，沟通及时`。
8. 点击 `评价`。

验证点：

- 订单状态变为 `已评价`。
- 说明确认收货、评价创建和订单最终状态都已完成。

### Step 11：卖家查看评价通知

1. 使用 `seller_demo / Seller@123` 登录。
2. 打开 `/notifications`。
3. 查找通知标题 `收到新的交易评价`。
4. 点击 `已读`。

验证点：

- 通知内容包含拍品标题和 `5 星评价`。
- 页面提示 `已标记为已读`。
- 通知状态从 `未读` 变为 `已读`。

### Step 12：管理员查看统计与运维证据

1. 使用 `admin / Admin@123` 登录。
2. 打开 `/admin/dashboard`。
3. 点击左侧 `统计报表`。
4. 查看 `今日 GMV`。
5. 点击左侧 `运维终端`。
6. 查看 `操作日志`、`任务日志`、`异常记录`。
7. 点击 `订单结算补偿`，确认无重复订单。
8. 点击 `通知重试`。

验证点：

- `今日 GMV` 至少包含本次成交金额 `¥380`。
- `操作日志` 和 `任务日志` 可见。
- `订单结算补偿` 可重复执行但不应生成第二笔订单，体现一场拍卖最多一笔订单的幂等约束。
- 点击 `通知重试` 后出现 `通知：成功 ...，失败 ...`。
- 说明统计、运维补偿、通知重试等旁路能力不会阻塞主交易链路。

## 5. 自动化浏览器验证

已新增专用 Playwright 用例：

```text
frontend/tests/e2e/defense-flow.spec.ts
```

该用例使用真实 Next.js 页面、真实 API client 请求格式和浏览器操作路径，通过 Playwright route 构造稳定测试后端，避免依赖现场数据库中已存在的历史数据。它覆盖从注册、发布、审核、建拍、两次出价、支付、发货、收货、评价、通知已读，到统计与运维终端的完整页面链路。为了让浏览器测试在十几秒内稳定完成，用例中的测试后端把拍卖结束和订单结算压缩为可控状态；真实后端的“结束后结算”规则仍由 `scripts/test.sh http`、`scripts/test.sh risk` 和 CTest 覆盖。

单独运行答辩链路：

```bash
cd frontend
npm run test:e2e -- tests/e2e/defense-flow.spec.ts
```

也可以从项目根目录运行全部前端 E2E：

```bash
scripts/test.sh e2e
```

自动化用例验证点：

- 注册表单字段、登录会话、角色切换。
- 发布拍品字段、图片 URL、价格与加价幅度请求体。
- 管理员审核批准与创建拍卖请求体。
- 大厅到详情页的拍品展示。
- 两个买家依次出价并刷新当前价。
- 订单支付请求携带 `confirm_success=true` 和 `MOCK_WECHAT`。
- 卖家发货、买家收货、买家 5 星评价。
- 卖家通知中心已读操作。
- 管理端 GMV 与运维通知重试结果。

注意：该浏览器用例证明“前端页面操作链路和接口契约”可跑通；数据库事务一致性、并发出价、支付幂等、RBAC 负向和通知失败不回滚主交易等后端高风险规则，仍以 `scripts/test.sh http`、`scripts/test.sh risk`、`ctest --test-dir build --output-on-failure` 作为答辩证据。

## 6. 后端与数据库事实验证

答辩现场可补充运行：

```bash
scripts/test.sh http
scripts/test.sh risk
ctest --test-dir build --output-on-failure
```

讲解口径：

- `http`：启动真实 HTTP 服务，覆盖认证、拍品审核、拍卖、出价、订单、支付、履约、评价、统计和运维接口。
- `risk`：覆盖并发出价、拍卖结束竞争、支付回调幂等、缓存降级、通知失败和安全负向路径。
- `ctest`：覆盖 C++ 模块测试、数据库测试、集成流和专项高风险测试。

若需要展示数据库事实源，可在本地 MySQL 启动后进入数据库，查询拍品、拍卖和订单表。数据库名和 socket 以 `start.sh` 或当前配置实际输出为准，示例：

```sql
SELECT i.title, i.item_status, a.status, a.current_price
FROM item i
JOIN auction a ON a.item_id = i.item_id
WHERE i.title LIKE '答辩演示%';

SELECT order_no, final_amount, order_status, paid_at, completed_at
FROM order_info
WHERE final_amount >= 380
ORDER BY created_at DESC
LIMIT 5;
```

讲解重点：

- 页面展示不是静态截图。
- MySQL 是拍品、拍卖、出价、订单、支付等交易事实的唯一权威数据源。
- Redis 或前端乐观状态只做读优化和交互优化，不能替代后端事务结果。

## 7. 常见问题

### 7.1 图片添加失败

确认填写的是：

```text
http://127.0.0.1:3000/demo-auction.svg
```

并确认前端服务 `http://127.0.0.1:3000` 正在运行。发布页会真实加载图片并校验 URL，不能填写不可访问地址。

### 7.2 直接打开后端 API 出现 404

例如直接访问：

```text
http://127.0.0.1:18080/api/items
```

浏览器会发起 `GET /api/items`，而当前创建拍品接口是 `POST /api/items`，我的拍品列表是 `GET /api/items/mine`，所以直接打开可能返回统一 JSON `404`。答辩操作应从 `http://127.0.0.1:3000` 页面入口进行。

### 7.3 拍品或订单已有历史数据

这是正常情况。答辩时以标题 `答辩演示 iPad Air 5 64G 蓝色` 搜索或识别本轮数据；如果需要完全干净环境，先按部署脚本重建本地演示库，再重新执行本手册。

### 7.4 浏览器自动化失败但人工可访问

先单独运行：

```bash
cd frontend
npm run test:e2e -- tests/e2e/defense-flow.spec.ts
```

如果失败，查看 Playwright 输出的 screenshot、video 和 trace。自动化用例依赖 `frontend/public/demo-auction.svg` 和 Next.js dev server；不要删除 `frontend/public/` 下的演示图。
